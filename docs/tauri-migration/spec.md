# Tauri 迁移 Spec

状态：实施中。已确认的产品边界来自 [intent.md](./intent.md)；Q-01～Q-05 已于 2026-10-18 定案并据此实现。

日期：2026-10-18。代码迁移在 `feat/tauri-migration` 分支进行，尚未发布。

## 1. 事实、要求与设计的区分

- **现状事实**：由仓库代码或二进制检查确认，不代表必须保留其中的缺陷。
- **已确认要求**：用户已明确答复，见 intent 的 I-01～I-06。
- **技术设计**：本 spec 为满足要求提出的实现方案；具体接口名、目录布局和依赖版本在实施时确定。
- **待决策**：需要用户确定的产品行为，不提供隐含默认值。
- **待验证**：不能仅凭文件存在或静态检查承诺的兼容性与运行结果。

### 2.1 现有资源

- `public/realsgan/realesrgan-ncnn-vulkan.exe`：Windows x64 可执行文件。
- `public/realsgan/macos_realesrgan-ncnn-vulkan`：包含 x86_64 和 arm64 的 macOS Universal Binary，已有执行权限。
- `public/realsgan/vcomp140.dll`、`vcomp140d.dll`：仓库配套 DLL；不能仅凭文件存在认定运行依赖已齐全。
- `public/realsgan/models`：约 82 MB，含五组同名 `.param` / `.bin` 文件及 `chain.chn`。

macOS 二进制已通过 `-h` 输出命令行帮助；帮助列出 jpg/png/webp 输入。此检查不等于已完成 GPU 推理，也不证明每个模型均能成功使用。当前前端接受 `image/*`，与二进制实际格式能力的差异需要在迁移中给出明确反馈。

### 2.2 输出兼容基线

现有输出统一为 PNG，未传入额外倍率、GPU 或线程参数：

- 原目录模式：`/images/a.jpg` 输出为 `/images/a.jpg_opt.png`。
- 自定义目录模式：`/images/a.jpg` 输出到所选目录的 `a_opt.png`。

技术设计保留上述命名规则。重名处理按 Q-03 定案的自动改名执行：目标路径已存在或已被同批次占用时，依次尝试 `a_opt(1).png`、`a_opt(2).png`，绝不覆盖已有文件。不同目录下的同名输入在自定义输出目录中同样按此规则消解冲突。

## 3. 目标设计与职责

采用 Tauri 2 作为目标技术方案，保留现有 React、TypeScript、Vite、Tailwind 及页面组件。

### 3.1 前端

- 负责页面、输入选择、参数表单、预览和任务状态展示。
- 通过一层有类型的桌面接口调用 Tauri，不让页面继续依赖 `window.ipcRenderer` 或 Electron 类型。
- 选图使用原生文件对话框；拖入图片使用 Tauri 提供的本地路径事件。不能直接用浏览器 File.name 充当真实文件路径。
- 输入数据改为包含本地路径和显示名称的记录，保留原选图顺序；只改变桌面适配，不重做界面。
- 本地预览使用 `convertFileSrc`，按所选文件配置资源访问范围和 CSP。不能沿用关闭 webSecurity 的方式解决预览问题。
- 页面卸载时解除事件监听；重新挂载不得重复订阅，也不得通过重新订阅重复启动任务。

### 3.2 Rust 桌面层

- 负责二进制及模型资源定位、文件检查、输出目录准备和子进程生命周期。
- 持有批次、队列和任务状态；前端不再逐张循环驱动原生进程，避免状态分散。
- 首版保持当前串行处理方式，同一时间最多一个推理子进程；重复开始必须被后端拒绝。
- 执行固定的内置程序，用参数数组传递路径和模型名，不通过 shell 拼接命令。
- 处理日志与进度，向前端返回可区分的成功、失败和取消结果。
- 承接单实例、窗口激活、系统进度、外部链接等现有桌面能力。系统进度支持程度需在目标平台验证。

### 3.3 ESRGAN 进程

- 继续使用仓库现有二进制及模型，不修改算法、不自动替换资源。
- 维持现有参数集合：输入路径 `-i`、输出路径 `-o`、模型目录 `-m`、模型名称 `-n`。
- 首版不增加高级参数设置，不承诺迁移本身提高推理速度。

## 4. 功能与行为要求

### 4.1 输入、模型和输出

1. 保留点击选图、拖入多图、预览、删除和清空能力。
2. 对话框取消不清空已有选择，不产生处理任务。
3. 原生层检查输入为存在的文件；无法处理的格式、损坏图片和读取失败应给出明确失败原因。
4. 模型列表来自内置目录，仅列出具有同名 `.param` 和 `.bin` 的模型；执行时再次校验模型属于有效列表。
5. 保留默认模型 `realesrgan-x4plus-anime`；缺失时提示资源异常，不静默选择其他模型。
6. 自定义输出模式必须选择有效目录；保持原实现可创建缺失目录的能力，创建或写入失败必须反馈。
7. 原目录与自定义目录均按 2.2 定位输出；不修改输入图片。文件名中的空格、中文和特殊字符应按路径原样传递。
8. 不支持用户指定二进制或模型目录；不引入首次启动下载资源步骤。
9. 重名输出与同批次内目标冲突按自动改名处理（Q-03 定案），重复执行同一图片会生成新的递增文件名，不覆盖旧结果。

### 4.2 批次与结果

1. 提交批次时固定本批次的输入顺序、模型和输出设置，处理中界面操作不应修改已提交任务的参数。
2. 每个批次、每张任务有稳定标识。所有异步结果按标识关联，旧批次的日志或退出事件不得覆盖新批次状态。
3. 任务状态至少区分等待、执行中、成功、失败、已取消；Q-02 定案为立即终止，批次另有等待进程退出的「停止中」状态。
4. 进程启动成功只表示开始执行。退出码为零且目标文件存在、非空，并确认是本次任务生成的输出，才可报告成功；不得将旧输出误判为本次结果，日志出现 100% 也不能提前认定成功。
5. 启动失败、非零退出、非预期信号终止或缺失输出均报告失败，保留用于定位原因的退出信息和相关日志。
6. 后端异常不得让界面永久停留在处理中；每项任务最多产生一次最终结果。
7. 单张失败后继续处理剩余任务，失败项单独标记并保留原因（Q-01 定案）；取消不能被当作普通失败处理后自动继续。

### 4.3 停止与应用生命周期

停止策略已定案为立即终止（Q-02）：后端记录停止请求后立刻结束当前子进程，剩余任务标记为已取消。实现仍必须满足：

- 后端先记录停止请求，再处理后续调度，消除“取消后又启动下一张”的竞态。
- 重复点击停止不会重复完成任务、破坏状态或启动新任务。
- 取消与自然退出同时发生时，只生成一个一致的最终结果。
- 进程尚未退出时，不将应用显示成已经完全停止并允许启动重叠批次。
- 已完成的输出不因停止操作被删除。取消或失败产生的残缺输出，其保留或清理规则随 Q-02 补齐，不默认删除。

关闭窗口的行为已定案（Q-04）：视为取消任务并退出应用，三个平台行为一致，不区分 macOS 关窗与应用退出，也不提供后台续跑。

实际退出应用时必须明确处理仍在运行的子进程，不能依赖 WebView 被销毁来清理。若选择后台继续，还需补齐应用存活、任务结果保留和重新打开窗口的状态恢复规则；首版不擅自新增托盘、开机启动或跨应用重启续跑能力。

### 4.4 日志与进度

1. 同时消费 stdout 和 stderr，避免未读取的输出阻塞子进程；stderr 不直接等同于错误。
2. 按流处理不完整文本，兼容分段到达、多行到达、回车及换行，不假定一次读取就是完整的一行或一个百分比。
3. 仅对有效百分比更新进度，允许小数，限制在 0～100；无有效值时保留未知或上一次有效进度，不生成 `NaN`。
4. 新任务开始时重置单张进度；旧任务日志不得改变当前任务进度。
5. 页面和系统进度使用同一后端结果，成功、失败或取消结束后清理系统进度显示。
6. 日志缓存与推送应有边界，避免长任务不断增加内存占用；具体上限和节流值由实现测试确定。

### 4.5 页面与其他桌面能力

- 保留首页、FAQ、开源许可、问题反馈入口和现有页面布局；桌面技术相关说明随实际迁移更新。
- 外部网页链接交由系统浏览器打开，不在有原生权限的主窗口内导航到远程站点。
- 保留单实例与再次启动时聚焦窗口的能力。
- 保留调试控制台入口，其在发行构建中的可用方式需要按 Tauri 实际能力验证。
- 检查更新已定案（Q-05）：保留手动入口，由原生层请求既有接口并用 semver 比较版本号（线上 7.2.0 高于本地 7.1.0 即提示更新）；现有 hash 逻辑不移植，开发构建跳过比较。
- 更新检查与下载地址尚未验证；不得假设服务端已经支持 Tauri 产物，也不在本阶段调用接口进行发布或修改服务。

## 5. 原生接口契约草案

以下约定接口职责，不冻结函数名或具体序列化字段。

| 接口 | 输入与结果 |
| --- | --- |
| 获取模型 | 返回有效内置模型列表；资源缺失返回可展示的错误。 |
| 选择图片 / 目录 | 使用原生对话框返回路径，取消返回取消结果；前端浏览器 File 不作为推理路径来源。 |
| 提交批次 | 接收输入列表、模型、输出模式和目录；返回批次标识，重复提交或参数无效时拒绝。 |
| 停止批次 | 指定批次，返回停止请求处理结果；最终停止由任务终态确认，不以请求返回代替。 |
| 查询状态 | 返回当前批次、各任务状态和当前进度，供监听建立后同步状态，避免丢失早期事件。 |
| 任务事件 | 携带批次标识、任务标识、事件序号/顺序依据和状态；进度与结果必须归属具体任务。 |
| 错误结果 | 区分输入、输出目录、资源、启动、推理和应用通信错误；包含用户可理解的信息，必要时附退出码和诊断日志。 |

停止中的具体状态转移、失败后的后续任务状态和批次最终结果，须在 Q-01、Q-02 确认后补齐；不由接口草案隐含决定。

## 6. 资源、构建与安装

1. 新增 Tauri 工程，前端产物继续由 Vite 构建；移除 Electron main/preload 构建插件、运行依赖和打包配置。依赖清理由实际使用情况决定，不顺带升级或替换无关组件。
2. ESRGAN 作为 Tauri sidecar 打包；模型及必要 DLL 作为附加资源。只携带当前目标所需程序，避免把整个 public 作为前端资源重复嵌入。
3. sidecar 按目标 triple 准备文件名；macOS Universal 源文件具备双架构不代表 Tauri 打包配置可省略目标适配。最终选择双安装包或 Universal 安装包仍待评估。
4. 资源位置由 Tauri 路径接口解析，不依赖 `process.resourcesPath`、开发机绝对路径、源码 public 目录或启动时的工作目录。
5. 在开发运行和实际安装包中分别验证程序执行权限、模型定位、Windows DLL 加载与 macOS 签名兼容。
6. 默认延续现有 Windows NSIS、macOS DMG 的产物方向；应用标识、升级覆盖安装和安装路径兼容须先核对，不能仅凭沿用名称宣称能覆盖旧 Electron 版本。
7. 明确 Node、包管理器、Rust、平台编译工具和 WebView 前置条件；具体版本及最低操作系统要求经过评估后记录，不沿用 README 中的过期构建说明。
8. 不预设证书、签名服务、发布凭证或 CI 构建机已具备。本阶段不修改流水线；后续若扩展自动构建，需覆盖目标平台及资源准备。

| 支持目标 | 现有核心资源 | 发布前必须验证 |
| --- | --- | --- |
| Windows x64 | x64 exe 与配套 DLL | 安装、WebView 条件、依赖加载、GPU 推理、停止、中文路径。 |
| macOS Intel | Universal 文件中的 x86_64 架构 | 原生架构执行、资源定位、GPU 推理、停止、安装版权限与签名。 |
| macOS Apple Silicon | Universal 文件中的 arm64 架构 | 原生架构执行、资源定位、GPU 推理、停止、安装版权限与签名。 |

最低系统版本须同时满足 Tauri/WebView、二进制、GPU/驱动及实际安装包的要求。不能因现有代码包含 Windows 7 分支就承诺迁移后支持 Windows 7。

# Tauri 迁移 Intent

状态：实施中。范围与行为决策已确认，迁移已在 `feat/tauri-migration` 分支落地。

日期：2026-10-18（同日授权进入实施）。

配套规格：[spec.md](./spec.md)。

## 1. 意图

将当前基于 Electron 的 ESRGAN 桌面应用迁移到 Tauri。应用继续以调用现有 `realesrgan-ncnn-vulkan` 二进制为核心，不重写超分算法。

首版保留现有界面和功能，同时修复任务取消、失败判断和进度解析问题。本次工作先交付 intent 与 spec，不实施代码迁移。

## 3. 当前事实与迁移原因

当前界面使用 React、TypeScript、Vite 和 Tailwind。Electron 主进程负责窗口、文件夹选择、模型目录扫描、ESRGAN 子进程和部分桌面能力；preload 向前端暴露 IPC 和文件路径接口。

核心推理已经在独立二进制中实现，未绑定 Electron 的计算接口。因此迁移的主要对象是桌面外壳、前后端通信、进程管理和资源打包，现有前端与推理资源具备复用基础。

现有实现有以下需要解决的问题，证据及行为细节见 spec：

- 停止操作先等待后端，再设置前端停止标记，存在继续启动下一张图片的竞态。
- 非零退出码仍作为正常结果返回，前端未按退出结果判断任务成功或失败。
- 将任意 stderr 文本直接解析为百分比，可能产生 `NaN`；未处理流数据分段。
- 文件真实路径、`file://` 预览、资源路径和打包配置均依赖 Electron，需要替换。

用户尚未指定安装包体积、空闲内存或启动耗时目标。可以在实施时测量迁移前后数据，但不将“达到某个体积”“推理提速”作为未经确认的承诺。

## 4. 首版边界

### 包含

- 迁移桌面运行时及构建、打包流程。
- 保留选图、拖入图片、多图处理、预览、模型选择、输出目录设置、开始、停止、清空及删除图片等现有能力。
- 保留现有页面、外部链接和桌面能力；与 Tauri 的适配方式见 spec。
- 内置当前 ESRGAN 二进制、模型及运行所需配套资源。
- 修复取消、失败和进度相关问题，并形成可验证的任务结果。
- 在已确认的三个系统与架构组合上验证安装包中的真实推理链路。

### 不包含

- 首版之外的平台支持，包括 Linux、Windows ARM 和移动端。
- 用户替换二进制、自定义模型目录或在线下载模型。
- 重新设计现有界面、替换前端框架或重写超分算法。
- 新增倍率、GPU、tile、线程、TTA 等高级参数界面。
- 当前阶段的实现、构建、发布、提交或推送操作。

更新检查是现有功能，但首版采用何种迁移方式尚未确认，不在此擅自确定保留方式或删除。

## 5. 成功标准

1. 安装版应用在确认的平台上能够使用内置资源完成图片超分，不依赖源码目录中的文件。
2. 用户继续通过现有界面完成选图、选择模型、指定输出位置和批量处理。
3. 成功、失败、取消有明确区别；普通日志不会使进度显示异常。
4. 停止操作遵守最终确认的策略，且不存在取消后意外继续启动任务的竞态。
5. 文档中的待决策项得到用户答复后，相关行为和验收条件同步补齐。

具体可执行的验收项目见 [spec 的验收矩阵](./spec.md#8-验收矩阵)。目前未执行迁移后的构建或推理验收。
